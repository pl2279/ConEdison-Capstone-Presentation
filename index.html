What failed

Four breakdowns, four fixes.

01
The first pass fed all six records into a single message — the models fused them into one narrative, impossible to score.
Fix: one record, one message. The broken run stays in the repo as proof.
02
In the rules-based pass, record 3 leaked into the session context of records 1–2.
Fix: one record, one API call — no record may ever see another.
03
Strict rules made the model overcautious — it marked a routine record as unresolved for no real reason.
Fix: an abstention cap — fewer than 1 in 20 routine records may be flagged.
04
The budget model invented a billing number, 8.2 kWh, where the answer key called for "unresolved".
Fix: a rule layer outside the model — any conflict forces unresolved, overriding whatever the model says.
We can only make this recommendation because of these failures — each one comes with a known, inexpensive fix.

What survived — and what a fix actually looks like

Throwing more people at cleanup isn't the answer.

AI processes every record
individually · outputs a clean version + verdict + written rationale
→
A rule layer has final say
station lookup table · drift table · conflict ⇒ unresolved
→
Humans handle only the flags
unresolved queue (<10%) + 1% spot-check
No manual pre-cleaning. Nobody hand-scrubs each record before the AI sees it — that approach can't scale to a 30-month backlog.
No full re-verification either. Every record carries its own paper trail — the model writes down its reasoning — which doubles as the audit lineage a regulator would ask for.
The evidence: the frontier model scored a perfect 6 of 6 against a locked, pre-written answer key — including correctly abstaining on the one record where "I don't know" was the right call.
Notes · ≈60s
1) 先立靶:解决方案不是"人清洗+AI+人核对"——那是商业上不可能的事,也是程序停摆的原因。2) 三格流程:AI 全量一遍过→规则层兜底→人只碰漏网之鱼+1%抽审。3) 两句话:没人预先清洗,没人全部复核;证据链=审计轨迹。4) 证据:旗舰模型 6/6,含诚实弃权。

What we recommend Con Edison do

Six instructions, straight.

1
Put this pipeline in place as the cleaning path for quarterly reporting and the backfill.Model cost ≈ $0.27/record measured — tens of thousands against the value of restarting the program; the manual path cannot meet the deadline at all.
2
Use the frontier-class model, not the cheapest.The cheap model was 7.6× cheaper and wrong exactly once — on the billing-conflict record.
3
Enforce the rules in code, not in the model's good intentions.Station dictionary · drift table · energy conflict ⇒ unresolved, always.
4
Use the per-record evidence trail as the audit trail.The model already writes down why — that is regulator-ready lineage, produced on every row.
5
Spend people where they add value: the flagged queue + a 1% audit.Nobody pre-cleans. Nobody re-checks everything. Those two things are what would make this commercially impossible.
6
Turn the six-record answer key into a standing regression test.Any model or prompt change must pass the six records before it ships.
The alternative isn't AI versus people. It's an automated cleaner versus a program that stays paused.

What could go wrong — and what we'd do about it

We asked it the same way we asked the models.

Silent wrong answers — the Kimi failure, repeated
Rule-checker outside the model + 1% audit sample; the regression test is the tripwire.
The unresolved queue floods
Abstention budget: under 1 in 20 ordinary records flagged; if it stays high, the prompt gets recalibrated, not shipped.
The station dictionary and drift table may not exist yet
Build them from exports and site records as step one of the pilot; every unmapped name is a flag, never a guess.
Real data may not look like our six records — ours are synthetic
Run a one-month pilot beside the current process, a person adjudicating every flag, before it becomes the process.
Models drift under the same name
The six-record regression test exists precisely for this.
To move forward, we need three things:
1 · Which energy figure is authoritative when records disagree — the charger's, the settlement's, or neither?
2 · How many real records carry conflicts like record 5, and how long does a person spend on one today?
3 · A de-identified sample — even 100 rows — to check whether our test records look like the real mess.
The prototype works. The next step needs real data.
